# mimamori インストールガイド（別のRaspberry Pi 4への新規セットアップ）

このドキュメントは、**すでに Raspberry Pi OS が起動しており、カメラモジュールが物理的に
接続済み**の Raspberry Pi 4 に、GitHub から mimamori をクローンして一から動かせる状態に
するまでの手順をまとめたものです。

- LINE通知の設定やリージョン（領域）のキャリブレーションなど、Pi固有・設置場所固有の
  詳細な設定手順は [設定ガイド.md](設定ガイド.md) を参照してください。本ドキュメントは
  そこに進むための土台（クローン・依存パッケージのインストール）に絞っています。
- プロジェクト全体の仕様は [../SPEC.md](../SPEC.md)、開発者向けの概要は
  [../README.md](../README.md)（英語）にあります。

## 1. 前提条件

- Raspberry Pi 4（Raspberry Pi OS 64bit）が起動済みで、インターネットに接続されていること
- カメラモジュール（OV5647センサーなど、CSI接続）が接続済みで、以下のコマンドで認識される
  ことを確認しておく

  ```bash
  rpicam-hello --list-cameras
  ```

  カメラが一覧に表示されない場合は、`raspi-config` でカメラインターフェースが有効になって
  いるか確認してください（Raspberry Pi OSの新しいバージョンではデフォルトで有効なことが
  多いです）。

## 2. 必要なシステムパッケージのインストール

```bash
sudo apt update
sudo apt install -y git python3-venv python3-picamera2 python3-gpiozero python3-pil.imagetk
```

各パッケージの用途:

| パッケージ | 用途 |
|---|---|
| `git` | GitHubからのクローンに使用 |
| `python3-venv` | Python仮想環境（venv）の作成に使用 |
| `python3-picamera2` | カメラ制御ライブラリ（`--system-site-packages` で仮想環境に引き継ぐ） |
| `python3-gpiozero` | GPIO制御ライブラリ（将来のPIRセンサー拡張用。現時点では未使用） |
| `python3-pil.imagetk` | `scripts/edit_regions.py` / `scripts/preview.py`（GUIツール）に必要 |

## 3. GitHubからのクローン

このリポジトリは公開（public）リポジトリなので、認証なしでHTTPS経由でクローンできます。

```bash
cd ~
git clone https://github.com/anakai000/mimamori.git
cd mimamori
```

（このPiから将来 `git push` する予定がある場合は、SSH鍵を作成してGitHubアカウントに
登録し、リモートURLを `git@github.com:anakai000/mimamori.git` に変更してください。単に
動かすだけであれば不要です。）

## 4. Python仮想環境のセットアップ

`--system-site-packages` を付けることで、手順2でapt導入した `picamera2` / `gpiozero` を
仮想環境から使えるようにします。

```bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
```

> **補足:** `requirements.txt` は `opencv-python-headless<5` を指定しています。OpenCV
> 5.0以降は `cv2.dnn.readNetFromCaffe`（このプロジェクトが人物検出に使うMobileNet-SSD
> モデルの読み込みに必要）が廃止されているためです。素直に `pip install -r requirements.txt`
> を実行していれば問題ありません。

動作確認（カメラ本体は使わないユニットテストのみ）:

```bash
python -m pytest
```

すべて `passed` になれば、Pythonまわりのセットアップは完了です。

## 5. 検出モデルの取得

人物検出用のMobileNet-SSD（Caffeモデル）を `models/` に配置します。手順の詳細は
[../models/README.md](../models/README.md)（英語）にありますが、要点は以下の2ファイルを
`models/` ディレクトリに置くことです（サイズが大きいためリポジトリには含まれていません）。

- `models/MobileNetSSD_deploy.prototxt`
- `models/MobileNetSSD_deploy.caffemodel`

もう1台のPiで既にこれらのファイルを用意済みであれば、`scp` などでコピーしてくるのが
最も簡単です。

```bash
# 例: 元のPiから新しいPiへコピーする場合（新しいPi側で実行）
scp anakai@<元のPiのホスト名またはIP>:~/mimamori/models/MobileNetSSD_deploy.prototxt models/
scp anakai@<元のPiのホスト名またはIP>:~/mimamori/models/MobileNetSSD_deploy.caffemodel models/
```

## 6. 設定ファイルの準備

### 6-1. LINE通知の設定

```bash
cp .env.example .env
```

`LINE_CHANNEL_ACCESS_TOKEN` と `LINE_TO_USER_ID` を設定する必要があります。これは
LINE Messaging APIのチャネルに紐づく値です。**同じLINE公式アカウント/チャネルを使い回す
場合**は、元のPiの `.env` の値をそのままコピーして構いません。**新しいチャネルを作る場合**
は、[設定ガイド.md](設定ガイド.md) の「4. LINE Messaging API の設定」を参照してください。

### 6-2. リージョン（領域）とドア開閉のキャリブレーション

`config/regions.yaml`（ドア・ベッド・ソファ・テーブルの領域）と `config/config.yaml` の
`door.closed_edge_density` / `door.open_edge_density` は、**カメラの設置場所ごとに
固有の値**です。別のPi・別の部屋にそのまま流用することはできません。

[設定ガイド.md](設定ガイド.md) の「5. 部屋のリージョン設定」「6. ドアの開閉判定の
キャリブレーション」の手順に従って、このPi・この設置場所用に必ず取り直してください。
`scripts/edit_regions.py`（GUIツール）を使うと視覚的に設定できます。

### 6-3. その他のしきい値

`config/config.yaml` の `state_timeouts_seconds`（異常検知までの時間）や
`detection.zone_debounce_frames` / `camera.fps` などは、まずは元のPiと同じ値のまま
始めて問題ありません。詳細は [設定ガイド.md](設定ガイド.md) の「7. 各種しきい値」を
参照してください。

## 7. 動作確認

```bash
source .venv/bin/activate
set -a; source .env; set +a
python main.py
```

ログにカメラの起動メッセージが表示され、エラーが出ずに動き続ければ成功です。
`Ctrl+C` で停止できます。

領域が正しく設定できているか目視確認したい場合は、以下のスクリプトも使えます
（先に `python main.py` は停止してください — カメラは同時に1プロセスしか使えません）。

```bash
python3 scripts/show_regions.py   # regions_preview.jpg に領域を描画して保存
python3 scripts/preview.py        # リアルタイムのプレビューウィンドウ（要ディスプレイ）
```

## 8. 起動時の自動起動設定（systemd）

動作確認が済んだら、Pi起動時に自動でmimamoriが立ち上がるようにします。

```bash
scripts/install_service.sh
```

内部的には `systemd/mimamori.service` を `/etc/systemd/system/` にコピーし、
`systemctl enable --now` を実行します（sudoパスワードを聞かれます）。ただし、この
ユニットファイルは `User=anakai` / `WorkingDirectory=/home/anakai/mimamori` のように
**元のPiのユーザー名・パスに固定**されています。新しいPiのユーザー名やクローン先の
パスが異なる場合は、`scripts/install_service.sh` を実行する前に
`systemd/mimamori.service` を編集し、`User=` と `WorkingDirectory=` /
`EnvironmentFile=` / `ExecStart=` 内のパスを実際の環境に合わせて書き換えてください。

以降の運用（開始・停止・ログ確認など）は [../README.md](../README.md) の
「Helper scripts」セクション、日々の設定変更は [設定ガイド.md](設定ガイド.md) を
参照してください。

## 9. うまくいかないときは

- `pip install -e .` や `import mimamori` が失敗する: 仮想環境を
  `--system-site-packages` 付きで作り直したか確認してください。
- カメラが `RuntimeError: picamera2 is not available` で失敗する: `python3-picamera2`
  がaptでインストールされているか、venvが `--system-site-packages` 付きか確認してください。
- 人物検出でエラーになる: `models/` に2つのモデルファイルが正しく配置されているか確認
  してください（手順5）。
- LINE通知が届かない、領域の判定がおかしい: [設定ガイド.md](設定ガイド.md) の
  「9. うまく動かないときは」も合わせて確認してください。
