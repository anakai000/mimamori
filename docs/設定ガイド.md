# mimamori 設定ガイド

このドキュメントは、Raspberry Pi 4 上で mimamori を動かすために必要な設定手順をまとめたものです。
プロジェクト全体の仕様は [SPEC.md](../SPEC.md)、開発者向けのセットアップ概要は
[README.md](../README.md) を参照してください。本ドキュメントは「実際に自宅で設定する人」向けに、
手順を一つずつ日本語で説明します。

## 1. 前提条件

- Raspberry Pi 4（Raspberry Pi OS 64bit）
- カメラモジュール（OV5647センサー、CSI接続）で、**IRカットフィルターをレンズから取り外し済み**であること
  - フィルターを外すと夜間の暗視性能が上がる一方、日中の映像は色が薄く/ピンクがかって写ります
  - 暗闇での撮影には赤外線（IR）照明が別途必要です（850nm/940nmのIR LEDなど）。本プロジェクトの
    範囲外なので、部屋に設置しておいてください
- LINE Messaging API のチャネル（後述の手順4で作成します）

## 2. ソフトウェアのセットアップ

Pi上のターミナルで、プロジェクトディレクトリ（`mimamori/`）に移動してから実行します。

```bash
# システム側のカメラ・GPIOライブラリ（未導入の場合のみ）
sudo apt install python3-picamera2 python3-gpiozero

# 仮想環境を作成（--system-site-packages でシステムのpicamera2/gpiozeroを引き継ぐ）
python3 -m venv --system-site-packages .venv
source .venv/bin/activate

# 依存パッケージのインストール
pip install -r requirements.txt
pip install -e .
```

動作確認（テストの実行、カメラ本体は使いません）:

```bash
python -m pytest
```

## 3. 検出モデルの準備

人物検出には MobileNet-SSD（Caffeモデル）を使用します。以下の2ファイルを `models/` ディレクトリに
配置してください（サイズが大きいためgit管理対象外です）。

- `models/MobileNetSSD_deploy.prototxt`（ネットワーク構造。小さいテキストファイル）
- `models/MobileNetSSD_deploy.caffemodel`（学習済み重み。約23MB）

入手方法や、別モデルに差し替える場合の注意点は [`models/README.md`](../models/README.md)
（英語）に記載しています。

## 4. LINE Messaging API の設定

通知には LINE Notify（サービス終了済み）ではなく、LINE **Messaging API** を使います。

1. [LINE Developers](https://developers.line.biz/) にログインし、プロバイダーを作成
2. 「Messaging API」チャネルを新規作成
3. チャネルの管理画面で「チャネルアクセストークン（長期）」を発行し、控えておく
4. 作成したチャネルの公式アカウントを、通知を受け取りたいLINEアカウントで「友だち追加」する
5. 通知先の `userId` を取得する（例: Webhookを一時的に有効にし、自分から公式アカウントに
   メッセージを送った際のWebhookイベントに含まれる `source.userId` を確認する）

取得した2つの値を `.env` ファイルに設定します。

```bash
cp .env.example .env
```

`.env` を編集:

```ini
LINE_CHANNEL_ACCESS_TOKEN=（手順3で発行したトークン）
LINE_TO_USER_ID=（手順5で取得したuserId）
```

`.env` は `.gitignore` 対象なので、git には commit されません（トークンなどの秘密情報のため）。

### スナップショット画像の公開URL（任意）

LINE Messaging API は画像メッセージを送る際、**LINE側のサーバーが取得できる公開HTTPS URL**が
必要です（LINE Notifyのようにファイルを直接アップロードする方式ではありません）。

Piにその仕組み（自宅サーバーの公開設定やクラウドストレージへのアップロードなど）を用意できる場合は、
`.env` の `SNAPSHOT_PUBLIC_URL_BASE` にそのベースURLを設定してください。

```ini
SNAPSHOT_PUBLIC_URL_BASE=https://your-host.example.com/snapshots
```

設定しない場合、異常検知時のアラートは**テキストのみ**送信されます（スナップショット画像自体は
Pi上の `/tmp/alert.jpg` には保存されます）。

## 5. 部屋のリージョン（領域）設定

`config/regions.yaml` に、ドア・ベッド・ソファ・テーブルの4つの領域を、カメラ映像上のピクセル座標
（多角形）で指定します。現在の値はすべてプレースホルダーなので、実際の設置環境に合わせて
書き換える必要があります。

1. カメラの設置場所を決めたら、実際の解像度でスナップショットを撮影します。

   ```bash
   rpicam-still -o snapshot.jpg --width 1296 --height 972
   ```

   （`1296x972` は `config/config.yaml` の `camera.size` と一致させてください）

2. `snapshot.jpg` をピクセル座標が確認できる画像編集ソフト（GIMPなど）で開き、以下4つの領域それぞれの
   角の座標 `[x, y]` を読み取ります。
   - `door`: 寝室からトイレへのスライドドア
   - `bed`: ベッド
   - `sofa`: ソファ
   - `table`: テーブル

3. `config/regions.yaml` の該当箇所を、読み取った座標に書き換えます。各領域は3点以上の
   `[x, y]` のリストで、閉じた多角形になるように指定します（自己交差しなければ順序は自由）。

   ```yaml
   bed:
     - [120, 300]
     - [520, 300]
     - [520, 650]
     - [120, 650]
   ```

## 6. ドアの開閉判定のキャリブレーション

トイレのスライドドアが「開いている」か「閉まっている」かは、ドア領域内の映像のエッジ（輪郭）の
密度（Canny edge density）から推定します。IRカットフィルターを外しているため色情報に頼れず、
この方式を採用しています。以下の手順で、`config/config.yaml` の `door.closed_edge_density` /
`door.open_edge_density` の2つの値を決めてください。

1. ドアを**閉めた状態**で1枚、**開けた状態**で1枚、スナップショットを撮影する
2. それぞれの画像から、`config/regions.yaml` の `door` 領域部分を切り出す
3. 以下のように `mimamori.door.edge_density` 関数を使ってエッジ密度を計算する

   ```bash
   source .venv/bin/activate
   python3 - <<'PY'
   import cv2
   from mimamori.door import edge_density

   image = cv2.imread("door_closed.jpg")
   x1, y1, x2, y2 = 0, 0, 100, 200  # config/regions.yaml の door 領域に合わせて調整
   roi = image[y1:y2, x1:x2]
   print("edge density:", edge_density(roi))
   PY
   ```

4. 「閉」の画像で得た値を `closed_edge_density` に、「開」の画像で得た値を
   `open_edge_density` に、それぞれ `config/config.yaml` に設定する

## 7. 各種しきい値（`config/config.yaml`）

`state_timeouts_seconds` は、各状態に一定時間以上とどまった場合に異常（ANOMALY）として
通知するまでの秒数です。用途に応じて調整してください。

| 状態 | デフォルト | 説明 |
|---|---|---|
| `OTHER` | 180秒（3分） | 部屋のどこにも該当しない移動中の状態 |
| `RESTROOM` | 600秒（10分） | トイレ内に長時間とどまっている（転倒などのリスク） |
| `SOFA` | 3600秒（1時間） | ソファに長時間 |
| `TABLE` | 3600秒（1時間） | テーブルに長時間 |
| `BED` | `null`（無制限） | 就寝中は長時間でも異常としない |

`detection.confidence_threshold`（デフォルト0.5）は人物検出の信頼度しきい値、
`detection.process_interval_seconds`（デフォルト0.5秒）はどのくらいの間隔で映像を処理するかです。
誤検知が多い場合はしきい値を上げる、反応が遅い場合は間隔を短くする、といった調整をしてください。

## 8. 起動方法

### 手動起動（動作確認用）

```bash
source .venv/bin/activate
set -a; source .env; set +a
python main.py
```

### 常時稼働（systemdサービス化）

Piの起動時に自動で立ち上がるようにする場合:

```bash
sudo cp systemd/mimamori.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mimamori.service
```

状態確認・ログ確認:

```bash
sudo systemctl status mimamori.service
journalctl -u mimamori.service -f
```

`systemd/mimamori.service` 内のユーザー名・パス（`/home/anakai/mimamori` など）が
実際の設置環境と異なる場合は、事前に書き換えてください。

## 9. うまく動かないときは

- 通知が来ない: `.env` の `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_TO_USER_ID` が正しいか、
  公式アカウントを「友だち追加」済みかを確認してください。
- 状態が正しく切り替わらない: `config/regions.yaml` の座標が実際のカメラ映像とズレていないか、
  スナップショットを撮って確認してください。
- ドアの開閉が誤判定される: 手順6のキャリブレーションをやり直し、`closed_edge_density` /
  `open_edge_density` の値を実際の映像から取り直してください（照明条件が変わると再調整が必要な
  場合があります）。
