# mimamori 設定ガイド

このドキュメントは、Raspberry Pi 4 上で mimamori を動かすために必要な設定手順をまとめたものです。
プロジェクト全体の仕様は [SPEC.md](../SPEC.md)、開発者向けのセットアップ概要は
[README.md](../README.md) を参照してください。本ドキュメントは「実際に自宅で設定する人」向けに、
手順を一つずつ日本語で説明します。

**別のPiに新規セットアップする場合**は、まず [インストールガイド.md](インストールガイド.md)
（GitHubからのクローン、依存パッケージのインストール）を先に行ってから、本ドキュメントに
進んでください。

## 1. 前提条件

- Raspberry Pi 4（Raspberry Pi OS 64bit）
- カメラモジュール（OV5647センサー、CSI接続）。標準の（IRカットフィルター付きの）モジュールを
  想定しています。暗闇での撮影が必要な場合は、別途赤外線（IR）照明、またはIRカットフィルターを
  外したNoIR相当のモジュールへの交換を検討してください（本プロジェクトの範囲外です）
- LINE Messaging API のチャネル（後述の手順4で作成します）

## 2. ソフトウェアのセットアップ

Pi上のターミナルで、プロジェクトディレクトリ（`mimamori/`）に移動してから実行します。

```bash
# システム側のカメラ・GPIOライブラリ（未導入の場合のみ）
sudo apt install python3-picamera2 python3-gpiozero

# 仮想環境を作成（--system-site-packages でシステムのpicamera2/gpiozeroを引き継ぐ）
python3 -m venv --system-site-packages .venv
source .venv/bin/activate

# 依存パッケージのインストール
pip install -r requirements.txt
pip install -e .
```

動作確認（テストの実行、カメラ本体は使いません）:

```bash
python -m pytest
```

## 3. 検出モデルの準備

人物検出には MobileNet-SSD（Caffeモデル）を使用します。以下の2ファイルを `models/` ディレクトリに
配置してください（サイズが大きいためgit管理対象外です）。

- `models/MobileNetSSD_deploy.prototxt`（ネットワーク構造。小さいテキストファイル）
- `models/MobileNetSSD_deploy.caffemodel`（学習済み重み。約23MB）

入手方法や、別モデルに差し替える場合の注意点は [`models/README.md`](../models/README.md)
（英語）に記載しています。

> **注意:** OpenCV 5.0 以降は `cv2.dnn` からCaffeモデルの読み込み機能（`readNetFromCaffe`）が
> 廃止されています。`requirements.txt` / `pyproject.toml` では `opencv-python-headless<5` を
> 指定済みなので、`pip install -r requirements.txt` を素直に実行していれば問題ありません。もし
> `AttributeError: module 'cv2.dnn' has no attribute 'readNetFromCaffe'` が出た場合は、
> `pip install "opencv-python-headless<5"` で入れ直してください。

## 4. LINE Messaging API の設定

通知には LINE Notify（2025年3月にサービス終了済み）ではなく、LINE **Messaging API** を使います。
2024年9月の仕様変更により、LINE Developers Console から直接 Messaging API チャネルを作成する
ことはできなくなっており、**LINE公式アカウントマネージャー経由でアカウントを作成**する必要が
あります。

### 4-1. LINE公式アカウントの作成とMessaging APIの有効化

1. https://account.line.biz/signup にアクセスし、LINEアカウントまたはメールアドレスで
   ビジネスIDを登録する（**個人利用でよく、法人登記などは不要**です。名前とメールアドレスの
   入力のみで進められます）
2. 表示される申し込みフォームでLINE公式アカウントを作成する（「サービス地域」欄はドロップダウンで
   選べます。デフォルトで意図しない国が選ばれていることがあるので確認してください）
3. https://manager.line.biz/ （LINE公式アカウントマネージャー）に**PCまたはスマホのブラウザで**
   ログインする（**スマホの専用アプリではなく、ブラウザからのみMessaging APIの有効化操作が
   可能**です）
4. 作成したアカウントを選び、右上の「設定」→ 左メニューの「Messaging API」を開く
5. 「Messaging APIを利用する」ボタンを押し、プロバイダーを作成（または既存のものを選択）して
   「同意する」を押す
   - **一度割り当てたプロバイダーは後から変更できません**
6. 同じ画面の「応答設定」で以下を確認・変更する
   - **Webhook: オン**（デフォルトはオフなので、必ず変更する）
   - **チャット: オフ**（オンのままだと、送られたメッセージがWebhookではなく手動チャット用の
     受信箱に流れてしまいます）
   - 「あいさつメッセージ」「応答メッセージ」はオンのままで問題ありません（Webhookの動作には
     影響しません）

### 4-2. チャネルアクセストークンの取得

1. https://developers.line.biz/console/ に手順4-1と同じアカウントでログインする
   （LINE Developers Console と LINE公式アカウントマネージャーは別の画面ですが、同じ
   アカウントで両方にログインでき、手順4-1で作成したチャネルが自動的にここに現れます）
2. 対象のプロバイダー→チャネルを開き、「Messaging API」タブを選択する
   （「チャネル基本設定」タブにあるのは Channel ID / Channel secret で、これらは
   Webhookの署名検証に使うもの。今回必要な**チャネルアクセストークン**は別物です）
3. 「チャネルアクセストークン（長期）」の「発行」ボタンを押し、表示された値を控える

### 4-3. 公式アカウントを友だち追加する

同じ「Messaging API」タブに表示されているQRコードまたはBot basic ID（`@`で始まるID）を使い、
通知を受け取りたいLINEアカウントのスマホから「友だち追加」する。

### 4-4. 通知先の userId を取得する

`GET /v2/bot/followers/ids` で友だちのuserId一覧を取得できる想定でしたが、実際に試したところ
`{"message":"Access to this API is not available for your account"}` となり、多くの
アカウントでこのエンドポイントは使えません。代わりに、実際にメッセージを送ってWebhookで
受け取る方法を使います。

1. ブラウザで https://webhook.site を開く（サインアップ不要）。ページを開くと固有のURL
   （例: `https://webhook.site/xxxxxxxx-xxxx-...`）が自動的に表示されるので控える
2. Developers Consoleの「Messaging API」タブ →「Webhook設定」で、Webhook URLに手順1のURLを
   貼り付けて「更新」→「検証」を押す（webhook.siteは常に200を返すので検証は成功するはず）
   - なお、応答設定の「Webhook」がオン（手順4-1参照）になっていないと、検証は成功しても
     実際のメッセージイベントは飛んできません
3. 手順4-3で友だち追加したLINEアカウントから、公式アカウントに何かメッセージを送る
   （例:「テスト」）
4. webhook.siteの画面に戻ると、左側に新しいリクエストが追加されている。それをクリックし、
   本文（JSON）内の `events[0].source.userId` の値（`U`から始まる文字列）を確認する
   - `destination` フィールドはボット自身のIDなので、これと混同しないよう注意
   - 最初に表示される、`events` が空配列 `[]` のリクエストは「検証」ボタンによる疎通確認用の
     ダミーで、実際のメッセージではありません

取得した2つの値（チャネルアクセストークン・userId）を `.env` ファイルに設定します。

```bash
cp .env.example .env
```

`.env` を編集:

```ini
LINE_CHANNEL_ACCESS_TOKEN=（手順3で発行したトークン）
LINE_TO_USER_ID=（手順5で取得したuserId）
```

`.env` は `.gitignore` 対象なので、git には commit されません（トークンなどの秘密情報のため）。

### 4-5. 動作確認

設定した2つの値で実際にプッシュメッセージが届くか、コード変更なしで確認できます。

```bash
source .venv/bin/activate
set -a; source .env; set +a
python3 -c "
from mimamori.line_notifier import LineNotifier
import os

notifier = LineNotifier(os.environ['LINE_CHANNEL_ACCESS_TOKEN'], os.environ['LINE_TO_USER_ID'])
notifier.send_alert('mimamori setup test: if you see this, push notifications are working.')
print('sent OK')
"
```

LINEにメッセージが届けば設定完了です。

### スナップショット画像の公開URL（任意）

LINE Messaging API は画像メッセージを送る際、**LINE側のサーバーが取得できる公開HTTPS URL**が
必要です（LINE Notifyのようにファイルを直接アップロードする方式ではありません）。

Piにその仕組み（自宅サーバーの公開設定やクラウドストレージへのアップロードなど）を用意できる場合は、
`.env` の `SNAPSHOT_PUBLIC_URL_BASE` にそのベースURLを設定してください。

```ini
SNAPSHOT_PUBLIC_URL_BASE=https://your-host.example.com/snapshots
```

設定しない場合、異常検知時のアラートは**テキストのみ**送信されます（スナップショット画像自体は
Pi上の `/tmp/alert.jpg` には保存されます）。

## 5. 部屋のリージョン（領域）設定

`config/regions.yaml` に、ドア・ベッド・ソファ・テーブルの4つの領域を、カメラ映像上のピクセル座標
（多角形）で指定します。現在の値はすべてプレースホルダーなので、実際の設置環境に合わせて
書き換える必要があります。

1. カメラの設置場所を決めたら、実際の解像度でスナップショットを撮影します。

   ```bash
   rpicam-still -o snapshot.jpg --width 1296 --height 972
   ```

   （`1296x972` は `config/config.yaml` の `camera.size` と一致させてください）

2. `snapshot.jpg` をピクセル座標が確認できる画像編集ソフト（GIMPなど）で開き、以下4つの領域それぞれの
   角の座標 `[x, y]` を読み取ります。
   - `door`: 寝室からトイレへのスライドドア
   - `bed`: ベッド
   - `sofa`: ソファ
   - `table`: テーブル

3. `config/regions.yaml` の該当箇所を、読み取った座標に書き換えます。各領域は3点以上の
   `[x, y]` のリストで、閉じた多角形になるように指定します（自己交差しなければ順序は自由）。

   ```yaml
   bed:
     - [120, 300]
     - [520, 300]
     - [520, 650]
     - [120, 650]
   ```

## 6. ドアの開閉判定のキャリブレーション

トイレのスライドドアが「開いている」か「閉まっている」かは、ドア領域内の映像のエッジ（輪郭）の
密度（Canny edge density）から推定します。暗い場所や照明条件が変わる状況でも色情報より頑健なため、
この方式を採用しています。以下の手順で、`config/config.yaml` の `door.closed_edge_density` /
`door.open_edge_density` の2つの値を決めてください。

1. ドアを**閉めた状態**で1枚、**開けた状態**で1枚、スナップショットを撮影する
2. それぞれの画像から、`config/regions.yaml` の `door` 領域部分を切り出す
3. 以下のように `mimamori.door.edge_density` 関数を使ってエッジ密度を計算する

   ```bash
   source .venv/bin/activate
   python3 - <<'PY'
   import cv2
   from mimamori.door import edge_density

   image = cv2.imread("door_closed.jpg")
   x1, y1, x2, y2 = 0, 0, 100, 200  # config/regions.yaml の door 領域に合わせて調整
   roi = image[y1:y2, x1:x2]
   print("edge density:", edge_density(roi))
   PY
   ```

4. 「閉」の画像で得た値を `closed_edge_density` に、「開」の画像で得た値を
   `open_edge_density` に、それぞれ `config/config.yaml` に設定する

## 7. 各種しきい値（`config/config.yaml`）

`state_timeouts_seconds` は、各状態に一定時間以上とどまった場合に異常（ANOMALY）として
通知するまでの秒数です。用途に応じて調整してください。

| 状態 | デフォルト | 説明 |
|---|---|---|
| `OTHER` | 180秒（3分） | 部屋のどこにも該当しない移動中の状態 |
| `RESTROOM` | 600秒（10分） | トイレ内に長時間とどまっている（転倒などのリスク） |
| `SOFA` | 3600秒（1時間） | ソファに長時間 |
| `TABLE` | 3600秒（1時間） | テーブルに長時間 |
| `BED` | `null`（無制限） | 就寝中は長時間でも異常としない |

`detection.confidence_threshold`（デフォルト0.5）は人物検出の信頼度しきい値、
`detection.process_interval_seconds`（デフォルト0.5秒）はどのくらいの間隔で映像を処理するかです。
誤検知が多い場合はしきい値を上げる、反応が遅い場合は間隔を短くする、といった調整をしてください。

## 8. 起動方法

### 手動起動（動作確認用）

```bash
source .venv/bin/activate
set -a; source .env; set +a
python main.py
```

### 常時稼働（systemdサービス化）

Piの起動時に自動で立ち上がるようにする場合:

```bash
sudo cp systemd/mimamori.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mimamori.service
```

状態確認・ログ確認:

```bash
sudo systemctl status mimamori.service
journalctl -u mimamori.service -f
```

`systemd/mimamori.service` 内のユーザー名・パス（`/home/anakai/mimamori` など）が
実際の設置環境と異なる場合は、事前に書き換えてください。

## 9. うまく動かないときは

- 通知が来ない: `.env` の `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_TO_USER_ID` が正しいか、
  公式アカウントを「友だち追加」済みかを確認してください。手順4-5の動作確認コマンドを
  先に試すと、問題が「LINE連携そのもの」か「mimamoriの検知ロジック」かを切り分けられます。
- LINEの公式アカウントから「このアカウントは、現在準備中のため...」等のメッセージが返ってくる/
  Webhookにメッセージイベントが来ない: 応答設定の「Webhook」がオフになっているか、「チャット」が
  オンになっている可能性があります。手順4-1の応答設定を確認してください。
- `pip install` した `opencv-python-headless` で `cv2.dnn.readNetFromCaffe` が
  `AttributeError` になる: OpenCV 5.0以降でCaffe対応が削除されたためです。手順3の注意書きの
  とおり `opencv-python-headless<5` を入れ直してください。
- 状態が正しく切り替わらない: `config/regions.yaml` の座標が実際のカメラ映像とズレていないか、
  スナップショットを撮って確認してください。
- ドアの開閉が誤判定される: 手順6のキャリブレーションをやり直し、`closed_edge_density` /
  `open_edge_density` の値を実際の映像から取り直してください（照明条件が変わると再調整が必要な
  場合があります）。
